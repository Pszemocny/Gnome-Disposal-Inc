## Problem

PP should wake up to "Your machines ate N gnomes while you slept: +$X" when Auto Crank feeds placed machines while the page is closed.

## Summary

- New file `src/systems/offline.ts`, class `Offline` with `boot()` and `update(dt)`. No other `src/` file edited.
- Ladder: step 2 (repo) for everything. Payout through `ctx.hole.earn`, money formatting through `core/format.ts`, the CONTINUE button reuses the `.btn big` class, easing from `core/ease.ts`, saving through `saveState`. The two average helpers (`avgTypeValue`, `avgTier`) copy the spawn odds of `Gnomes.pickSpawnType` and `rollTier`, because those functions roll dice and expose no odds.
- `boot()`: reads `gnome-boozed-seen` (ms), writes "now" at once, then pays only if away is 120 s to 8 h, Auto Crank > 0 and `state.placed` has a cannon (2.86/s), vacuum (5/s), black hole (12/s) or magnet (3/s), caps summed per machine. Eaten = `min(0.08 x autocrank x (1 + batch), cap) x away`; money = `eaten x avgTypeValue(level) x avgTier(level) x hole.valueScale x 0.5`. No XP. After paying it saves the state right away: the key already says "now", so closing the tab from the title menu (autosave only runs unpaused) would otherwise lose the payout.
- The L-shaped hanging magnet is the existing type `magnet` (`2026-10-20-magnet-arm-no-rim.md`), so it is counted with cap 3. There is no robot type in `src/` yet (`grep -rn robot src` returns nothing; the robots plan names it `'robot'`), so robots are not counted.
- `update()`: writes the key every 10 s of real time (`Date.now`), so it works whether it is called inside or outside the paused block.
- Card: `.offline-card`, CSS in a `<style>` element the module appends and removes with the card, z-index 35 (above the title menu at 30). Pop-in 0.35 s with `outBack` (scale 0 → 1.1 → 1), pop-out 0.2 s with `1 - inQuad`, both on `requestAnimationFrame` with real time, so they run while the game is paused. CONTINUE calls `audio.ensure()` then `audio.coin()`: before the first click the AudioContext does not exist, so a coin at load time would be silent.

### Wiring for the orchestrator (exact lines)

`src/core/context.ts`:
- with the other type imports: `import type { Offline } from '../systems/offline';`
- in `interface Ctx`, after `shop: Shop;`: `offline: Offline;`

`src/main.ts`:
- import: `import { Offline } from './systems/offline';`
- right after `ctx.machines.restore(state.placed);`:
  `ctx.offline = new Offline();`
  `ctx.offline.boot();`
- next to `ctx.hud.update(dt);` (outside the `if (!ctx.paused)` block): `ctx.offline.update(dt);`
  Reason: the key is then refreshed on the pause and title menus too, so time spent on a menu, when the machines do not run, is not paid as "away".

## Rejected

- Robots in the cap: rejected, no robot machine type exists in `src/` tonight. When it lands, one line `robot: <gnomes per s>` in `CAP` adds it.
- A coin sound when the card appears: rejected, the AudioContext only starts on the first click, so the sound plays on CONTINUE instead.

## Uncertain

- The plan makes "≤ 8 h" a condition, so 8 h 1 min away pays NOTHING and shows no card. If PP sleeps longer than 8 h after his last session, the feature looks broken. Clamping away to 8 h instead is one change: `if (away < MIN_AWAY || crank <= 0) return;` and `const eaten = ... * Math.min(away, MAX_AWAY);`. Built as the plan says; PP decides. **Orchestrator decision (2026-10-20):** clamp, so more than 8 h away pays for 8 h (`away = min(elapsed, MAX_AWAY)`); a long night must not look broken.
