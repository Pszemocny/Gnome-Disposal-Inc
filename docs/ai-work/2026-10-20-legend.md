## Problem

PP (Slack): "Dodaj legendę pod jakimś klawiszem o krasnalach, grzybach i innych mechanikach". The game has 12 gnome types, 6 mushrooms, ~50 upgrades and a dozen systems (events, contracts, moods, rain, slow-mo, STRIKE, offline pay, rebirth). Nothing in the game explains them in one place.

## Summary

Ladder: step 2 (reuse). The overlay reuses the shop's CSS classes (`.shop`, `.shop-win`, `.shop-head`, `.shop-tabs`, `.tab`, `.shop-rows`, `.shop-foot`, `.x`); the `<style>` element adds only cards, tables and key caps. Open/close copy `Blueprints.open/close` (pause, unlock, cancel placement, own Esc handler with `preventDefault`, the closing key taken out of `input.pressed`). Prices use `upgradeCost`, money uses `money()`.

What the player gets (L opens, L or Esc closes, the game is paused while open):
- Gnomes: one card per `GNOME_TYPES` entry: hat/shirt swatch, name, money multiplier, XP, behaviour words, walk speed, size, from which hole level, "not made by the factory" (weight 0), Boom share and blast reach from `BOOM_CHANCE`/`BOOM`, "can sleep as a statue" from `statue`. Then the `WEIGHT_TIERS` table (kg, size, money/XP, run speed).
- Mushrooms: one card per `MUSHROOMS` def: cap colour, name, effect, base duration, share of drops (`weight / total`), ACTIVE badge; above the cards the Spore Bag and Long Trip rows (name, level, desc from `UPGRADES`).
- Tools: the key table (`KEYS`, the only list of keys in the module) and every upgrade grouped by its shop tab: name, description, level/max, price now (`upgradeCost`, shards for Deep).
- Mechanics: `HOLE_LEVELS` table (current level highlighted), `LAND` table, combo with live window and cap from `ctx.hole`, trick shots, STRIKE, events, contracts (live list with targets for the current level, time, hard, "not possible now"), hole moods, rain, slow-mo, offline pay, rebirth with live `ctx.hole.shardsForRebirth()` and the Deep upgrades.

Decisions:
1. "???" rule: a gnome type is unknown until the hole reaches its `unlock` level or the player fed one (`stats.typesEaten`); the card stays (count = `GNOME_TYPES.length`) and says from which level it shows up. Upgrades: "???" while the hole level is too low, like the shop. Hole level unlock texts: "???" beyond the next level. Land names: shown up to the next buyable tier, like the shop. Mushrooms and Deep upgrades are always shown (they are explained, not secret).
2. Words without a data source live in one map `TEXT` keyed by gnome id or mechanic id; an id missing there gets `GENERIC` ("A gnome. Feed it to the hole."). The words carry no numbers, so they cannot drift from the code.
3. `EVENTS` in events.ts is not exported and `Contracts.defs` is private. The legend reads both at runtime when present (`eventsModule.EVENTS`, `ctx.contracts.defs`); without them the section shows only its `TEXT` line. Today: contracts list shows (the field exists at runtime), events list does not (not exported). One wiring line below makes the events table show.

Rejected:
- numbers for trick shots, STRIKE, moods, rain, slow-mo, offline pay and base mushroom drop chance: they are private constants or inline literals in hole.ts, strike.ts, moods.ts, weather.ts, slowmo.ts, offline.ts, mushrooms.ts; copying them into the legend would drift with the next balance pass (Night A changes them), so the legend explains these in words only → exporting tables from those files is a separate task.
- a per-type "behaviour" fallback map keyed by `behaviour`: the envelope asks for one map keyed by id with a generic line.
