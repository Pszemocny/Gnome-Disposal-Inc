## Problem

PP wants a daily challenge: the same map and the same factory gnomes for everybody on the same day, and its own leaderboard list. A daily run must never touch the player's real save.

## Summary

What the player gets:
- Title menu (normal game): a "Daily challenge <UTC date>" button opens `?daily`.
- `?daily` (or `?daily=YYYY-MM-DD`): a fresh run (money 0, hole level 1, Backyard). The title says "DAILY CHALLENGE <date> · 5 minutes" and has "Back to your yard". A tag in the bottom right counts down "DAILY <date> · m:ss" on game time (menus and pauses do not count).
- After 300 s the game pauses and the leaderboard opens with "DAILY <date> OVER". Submit or Skip (or Esc) goes back to the normal yard.
- The leaderboard has two tabs: ALL-TIME (old entries without a board land here) and DAILY <date>. It opens on the board of the current mode; a submit goes there. A rebirth inside a daily also goes to the daily board.
- The daily run never writes the real save (`blockSaves()` at import time), does not touch the offline "last seen" key, and its pause menu has no "Reset save".

Files: `src/systems/daily.ts` (new), `src/ui/leaderboard.ts`, `src/ui/menu.ts`, `src/main.ts` (import, `freshState()` in daily mode, two offline guards, `daily.update(dt)` after `ctx.legend.update()`).

Ladder:
- `fnv1a` + `mulberry32` (rung 6, ~15 lines): two independent seeded streams are needed (map via `Math.random`, factory via `rng.spawn`); `THREE.MathUtils.seededRandom` has one global state.
- `?daily` URL switch + reload (rung 2, same as `?lowfx`); `blockSaves()` and `freshState()` already existed (rung 2).
- Tabs reuse the shop/legend `.shop-tabs` / `.tab` CSS (rung 2). Menu buttons reuse the `data-a` click pattern (rung 2).

Deviations from the plan:
- `daily.update` also sets `ctx.paused = true` before `unlock()` (the shop/legend pattern). Without it the game keeps running behind the "OVER" form and the score could still grow after the run ended.
- The menu links are `<button class="btn" data-a="daily|yard">` handled in the existing click handler, not `<a class="btn">`: `.btn` has no anchor styling (underline, inline), and `style.css` is not this task's file.

Rejected:
- Blueprints in daily mode: `blueprints.ts` stores slots under its own key, so saving a layout during a daily overwrites the same slot in the yard. Not in the plan and not this task's file → separate order if wanted (one guard in `Blueprints` save: `if (daily.active) return`).
- Keeping `?lowfx` when the daily ends or on "Back to your yard": the plan sends the player to `location.pathname`; a Low-quality player who used `?lowfx` loses it on the way back. Built as planned.
