## Problem

PP asked for a celebration of big moments that is felt, not read. A BULLSEYE, the combo crossing 60 or 100, and an eaten King should freeze the game for a moment and then play it at quarter speed with a low "whoomp".

## Summary

- New file `src/systems/slowmo.ts`, class `Slowmo`, no other `src` file touched.
- `scale` getter: 0 for 0.08 s (freeze), 0.25 for 0.6 s, then eased back to 1 over 0.4 s with `outCubic` (Animation rule 2). 1 otherwise.
- `update(dt)` takes REAL dt. It compares `stats.bullseyes`, `stats.typesEaten.king` and `hole.combo` with the previous frame. Combo triggers only when it crosses 60 or 100 (previous below, now at or above), so a jump 98 → 101 counts too. The first call only records the counters, so a loaded save with old values does not trigger.
- At most one slow-mo per 5 s (real seconds, counted from the start of the last one). Triggers inside the cooldown are dropped, not queued.
- Sound: `audio.rumble(0.3)` exists (`src/core/audio.ts`, lowpass noise 140 → 40 Hz), used as planned.
- Ladder: step 2 for the easing (`src/core/ease.ts`) and the sound (`audio.rumble`); the class itself is step 6, minimum code.

### Wiring for the orchestrator (`src/main.ts`, `src/core/context.ts`)

`context.ts`, next to `contracts`:

```ts
import type { Slowmo } from '../systems/slowmo';
// in the ctx interface
  slowmo: Slowmo;
```

`main.ts`:

```ts
import { Slowmo } from './systems/slowmo';
// after ctx.contracts = new Contracts();
  ctx.slowmo = new Slowmo();
```

In `frame()`, replace the line `const dt = Math.max(0, Math.min(0.05, timer.getDelta()));` with:

```ts
    const realDt = Math.max(0, Math.min(0.05, timer.getDelta()));
    const dt = realDt * ctx.slowmo.scale;
```

Inside the `if (!ctx.paused)` block, right after `ctx.contracts.update(dt);`:

```ts
      ctx.slowmo.update(realDt);
```

After the block: `ctx.hud.update(dt);` becomes `ctx.hud.update(realDt);`. Also `state.stats.playTime += realDt;` and `codeCd -= realDt;` (play time and the cheat-code cooldown are wall-clock things).

Why these exact places:
- `slowmo.update` MUST get `realDt`. With the scaled dt the freeze (scale 0) would never end.
- Calling it after `hole.update` means a BULLSEYE scored this frame starts the freeze in this frame; the next frame is the first slowed one.
- Interpolation stays correct with no other change: `acc += dt` gets the scaled dt, so at 0.25 physics steps once every 4 frames and `renderAlpha = acc / timestep` walks 0, 0.25, 0.5, 0.75 between the steps; at 0 no step runs and alpha stays put, so the frame is frozen, not jittering. The 3-step cap and `acc = Math.min(acc, timestep)` are unaffected (the scaled dt is never larger than the real one).
- The 60 fps cap and `renderer.render` stay on real time (they do not use dt).
- Mouse look stays real time on its own: `player.ts` turns by `mouse.dx`, not by dt. Walking speed of the player is slowed with everything else (`player.update(dt)`), which is what a slow-mo looks like.
- While paused `update` is not called, so the timer stops; after unpause the slow-mo continues where it was. The pause menu is unaffected (it does not use dt).
