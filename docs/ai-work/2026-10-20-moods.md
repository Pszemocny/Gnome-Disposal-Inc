## Problem

The hole has no personality and the most valuable target never changes. PP wants the hole to whisper and the yard to have a changing "best target".

## Summary

- `Moods` class, `update(dt)` only, no saved state (a reload, rebirth or save without new keys just rolls a new wait).
- From hole level 2, every 150-200 s of game time the hole craves one type for 45 s. Pool = types with `weight > 0`, `unlock <= holeLevel`, never classic / blue / king. So Boom Gnome (weight 0, rolled by chance) and golden (weight 0) are never craved; the pool follows `gnomeTypes.ts` live, so a type removed or set to weight 0 by another agent drops out on its own.
- During a craving every frame sets `g.valueMult = 3` on the craved type and 1 on the rest (`hole.consume` already multiplies `g.valueMult`). At the end every gnome is set back to 1. Nothing else in `src` writes `valueMult` (only `gnomes.replace` copies it).
- Start: `hud.banner('THE HOLE CRAVES: ANGRY GNOMES', 'They pay x3 for 45 s')`, a `secret` toast with the same line, `audio.whisper()`. End: `hud.banner('THE HOLE IS SATED', ...)`. All three APIs exist; no new HUD element (no live countdown line: the HUD has no API for it and `hud.ts` is not mine).
- Taunts, checked every 10 s: `stats.longShots` grew → "Ooh."; throws since the last window with a gnome eaten reach 5 → "Five misses. Pathetic." At most one taunt per 20 s. Toast kind `secret` + `audio.whisper()`.
- Drabina: rung 2, reuses `hud.banner/toast`, `audio.whisper`, `g.valueMult`, `GNOME_TYPES`; no animation added (no animation rules apply), no allocations per frame beyond the `pool()` call once per craving.

```ts
import { Moods } from './systems/moods';
```
after the line that creates `ctx.contracts` (state must already be loaded, the constructor reads `ctx.state.stats`):
```ts

```

```ts
      ctx.moods.update(dt);
```
