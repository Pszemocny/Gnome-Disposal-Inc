### Layout rule (what the implementer cannot guess)
- `list` = upgrades of the tab in data order (Land: `LAND` tiers). `tiers` = sorted distinct `u.hole ?? 1` (Land: `t.hole`).
- `col(u) = max(tiers.indexOf(u.hole ?? 1), col(parent) + 1)` when the parent is in the tab (Land: parent = previous tier), else the tier column.
- Rows: `free: number[]` per column, all 0. Walk `list`; a root takes `row = free[col]`; its children (data order, recursive) take `row = free[childCol] <= parentRow ? parentRow : free[childCol]` for the first child and `free[childCol]` for the rest; after each placement `free[col] = row + 1`.
- Cell `CW = 108`, `CH = 86`; node box 88 x 78 at `left = col * CW`, `top = row * CH`; `w = cols * CW - 20`, `h = rows * CH - 8`. Edge: `M${pc*CW+88} ${pr*CH+26} H${pc*CW+98} V${cr*CH+26} H${cc*CW}` (badge centre y = 26).
- Results: Plow 3 x 3 (kick c0 r0; blower c0 r1 → blowPower c1 r1, blowRange c1 r2; tractor c1 r0 → plowWidth c2 r0). Magnet 2 x 3. Factory 4 x 2 (factorySpeed c0 r0 → batch c1 r0 → autocrank c3 r0; value c0 r1; permit c1 r1; glue c2 r0). Movement 2 x 4. Tools 7 x 5. Combos 3 x 2. Bonuses 2 x 4. Land 4 x 1. Deep 1 x 5.

### Chosen variant
Every tab (Land and Deep included) goes through one `tree()` renderer: columns by hole tier and `requires`, rows packed; 14 item nodes show a PNG of their own model rendered once per session on a throw-away `WebGLRenderer`, 38 stat nodes and 4 land tiers show emoji; states are CSS classes with a CSS pulse, lit SVG edges, a WAAPI pop on buy and a `transform: scale(k)` fit for 640x360. Pros: no save migration, no per-frame cost, `ctx.renderer` never touched, every GL failure degrades to emoji per id, DOM contract (`[data-tab]`, `[data-buy]`, `[data-land]`, `.name`, `.cost`, `.tags`) kept. Cons: one GL context created and lost per session; a one-time stall on the first open; 11 px names need a hover to read stat effects. Cost (performance numbers): ~6 shader programs x 30-100 ms = 0.2-0.6 s once per session, 14 readbacks + 14 PNG encodes of a few ms each, ≤ 15 nodes and 4 paths per render, HTML per render ≤ 14 x 10-25 KB (data URL once per node). Risk (roast scenarios): pop vs pulse (R3), builder failure (R1 + row 30), stale description and scroll jump during a buying spree (R11, R12, review focus 3). Ladder: rung 2 for `rowData`/`badges`/`buy`/`deny`/key handling, rung 3 for CSS animations, SVG lines, WAAPI `animate`, canvas `toDataURL`, rung 4 for the installed three renderer, rung 6 only for the ~25-line tier layout and the ~60-line icon module.

### Rejected variant(s)
